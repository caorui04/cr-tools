# cr-tools 安装指导手册

> 面向首次部署者。本文档教你**把论文工作台装到自己的电脑上**。根据你的情况选一种方式即可（推荐方式 A：便携包，零安装）。

## 一、两种安装方式总览

| | **方式 A：便携包（推荐）** | **方式 B：源码构建** |
|---|---|---|
| 适合 | 普通使用者（只想用） | 开发者/维护者（想改代码） |
| 需要装什么 | **什么都不用装** | Node.js + Python |
| 步骤 | 解压 → 下模型 → 双击启动 | 4 步命令 |
| 体积 | full 6GB / lite 1.2GB | 源码 2MB + 依赖自动装 |
| 移动 | 整个文件夹可拷 U 盘随身 | 固定在开发机 |

---

## 二、方式 A：便携包安装（推荐）

### 1. 获取便携包
- **portable-full**（含全部模型，开箱即用，约 6GB）：自己用/离线环境
- **portable-lite**（无模型，约 1.2GB）：网络好时下载模型后与 full 等效；用于分享

### 2. 解压
把压缩包解压到任意位置（建议英文路径，如 `D:\cr-tools`；U 盘也行）。

### 3. （lite 包）下载模型
双击运行 `scripts\download-models.ps1`（或 `tools` 目录手动放置，清单见本文 §五）：

```powershell
powershell -ExecutionPolicy Bypass -File scripts\download-models.ps1
```
- 自动从**国内镜像**（hf-mirror.com）下载 3 个模型（共约 4.2GB）
- 下载失败的文件会提示**手动下载**（按 §五 表格操作）
- full 包跳过此步

### 4. 配置 Key（可选）
编辑 `pipeline\config.yaml`，填入你的 API Key（见 §四）。不填也能运行。

### 5. 启动
双击 **`start.bat`**（自动启动：管线服务 + 嵌入服务 + 主界面）。浏览器打开：
- 工作台：`http://127.0.0.1:3180`
- 管线状态：`http://127.0.0.1:8737/status`（显示 200 即正常）

### 5.1 论文项目与工作区（部署条件）
便携包**开箱即用**：启动后已有一个「**我的论文**」工作区和一个**空模板论文项目**（`data/pipeline/papers/p_demo`），工作台会自动弹出，可直接开始写。

- **预置工作区**「我的论文」：位于便携包 `papers\我的论文`，打开后工作台自动打开（auto-open）。换机器/U 盘插到别处时，`start.bat` 会自动把工作区路径适配到当前实际目录。
- **新建论文项目**：工作台顶部「📚 项目」旁「＋ 新建论文项目」→ 输入论文题目 → 自动建好项目 + 空模板草稿（含工作台功能/排版说明）。一个项目 = 一篇论文，多篇互不干扰。
- **论文数据根**：管线项目数据在便携包 `data\pipeline\papers\`；引用清单/草稿/版本记录都在各项目目录内（随 U 盘搬运）。

### 6. 验证
| 检查项 | 位置 | 预期 |
|---|---|---|
| 主界面 | 3180 | 工作台面板 + 对话区 |
| 管线 | 8737/status | 200 + 队列全 0 |
| 嵌入（full 包） | 8083 | 在线 |

## 三、方式 B：源码构建（开发者）

前置：Node.js ≥18（https://nodejs.org）、Python 3.11（https://www.python.org，勾选 Add to PATH）。

```powershell
# 1) 一键装依赖（DSH 平台 + Python 依赖 + 生成配置 + 部署 profile）
powershell -ExecutionPolicy Bypass -File scripts\setup.ps1

# 2) 下载模型（国内镜像优先；或手动按 §五）
powershell -ExecutionPolicy Bypass -File scripts\download-models.ps1

# 3) 编辑 pipeline\config.yaml 填入 Key（§四）

# 4) 启动
start.bat
```

`setup.ps1` 做了什么：检查 Node/Python → 本地安装 DSH 平台 → 创建 Python 虚拟环境并安装 87 个依赖（清华镜像）→ 生成 `config.yaml`（从模板）→ 部署项目级 DSH 配置（不污染你的用户目录）。

## 四、API Key 申请与配置

复制 `pipeline\config.yaml.example` 为 `pipeline\config.yaml`，填入以下 Key（**全部可选**——不填核心功能照常，仅对应云端/联网功能降级）：

| Key | 用途 | 申请地址 | 备注 |
|---|---|---|---|
| **DeepSeek API Key** | 云端分析后端（速览卡摘要/引用核验/翻译） | https://platform.deepseek.com | 注册即用，按量计费 |
| **百度千帆 AppBuilder Key** | 中文联网检索（百度学术） | https://cloud.baidu.com/product/AppBuilder（控制台 https://console.bce.baidu.com） | 免费 100 次/日 |
| **OpenAlex Key** | 国际联网检索 | https://developers.openalex.org（注册 email 获取） | 10000 credits/日 |
| DOAJ / arXiv | 开放 API | 无需 Key | — |

配置位置（config.yaml 内）：
```yaml
models:
  llm:
    cloud:
      api_key: "sk-你的DeepSeekKey"      # ← 云端分析
web_search:
  qianfan:
    api_key: "bce-v3/你的千帆Key"        # ← 中文联网检索
  openalex:
    api_key: "你的OpenAlexKey"            # ← 国际联网检索
```

## 六、启动验证与常见问题

### 启动后确认
1. 浏览器 `http://127.0.0.1:3180` 出现工作台
2. 顶栏「📚 论文工作台」打开后有面板（引用链/速览卡/检索/输入资料）
3. 入库监控 Tab 显示管线在线（文档/切块计数）

### 常见问题

**Q：start.bat 闪退？**
A：窗口一闪而过通常是 Python 路径问题。在 cmd 里手动运行 `pipeline\.venv\Scripts\python.exe -m server.main` 看报错；便携包用 `pipeline\runtime\python\python.exe`。

**Q：OCR 报"Paddle 无法打开模型"？**
A：PaddleOCR 模型缓存路径含中文时可能失败（已内置 8.3 短路径自动转换）；仍失败则手动设置环境变量 `PADDLE_PDX_CACHE_HOME` 到纯英文目录后重启。

**Q：lite 包没下模型就启动了，怎么办？**
A：管线可用（文本型入库/检索降级），OCR 相关功能会报错——补下模型（§五）后重启即可。

**Q：检索结果 score 恒为 0？**
A：向量库未建——提交文档入库后 M4 自动索引（需 BGE-M3 嵌入服务 8083 在线）。

**Q：端口被占用（3180/8737/8083）？**
A：说明已有 cr-tools 实例在跑（重复启动）。关闭旧的再启动；或改端口（start.bat 内 `--port` 与 config.yaml `http_port`）。

**Q：完全不懂命令行，还有救吗？**
A：有。用**方式 A 便携包 full 版**：解压 → 双击 start.bat → 浏览器打开——全程不需要命令行（下载模型那步双击 ps1 即可，或直接用 full 包）。
